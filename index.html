Like netcat, but over your own device mesh.

Noscat joins any computer you own into one private mesh: a laptop, a Raspberry Pi in a closet, a VPS, a desktop at work, an Android phone. Each device is addressed by its own Nostr key, every byte is end-to-end encrypted, and nothing needs root, an account or a company in the middle.

Think Tailscale, but

Your devices run the mesh themselves.

No company in the control plane

Membership is a Marmot group (MLS, the IETF group encryption standard) carried by ordinary Nostr relays. Use public ones or run your own.

No coordinator, no owner

Every member can verify who is in, and any member can invite or remove. Lose a device and the mesh carries on.

No root, no kernel module

Everything runs in userspace, on a Raspberry Pi as well as a Windows desktop. The CLI is a single binary, and Android has a native app.

No accounts

Each device generates its own keypair, and its npub is its address. There is no sign-up, email address or phone number.

How it works

Membership goes through a relay. Your data doesn't.

Membership over Nostr

Invitations, removals, key packages and presence travel as MLS messages through public relays. The relays never learn who is in a mesh, what the devices are called or where they are.

Data device to device

Files, chat and forwarded ports go over FIPS, an encrypted overlay keyed by the same identities, with QUIC streams on top. Devices behind NAT connect directly where they can and through a reachable member otherwise.

Your relay, members only

noscat-relay serves only your mesh's devices, which log in with their keys. Your devices stop using public relays, and because the relay also runs STUN, no public STUN server learns their addresses.

The server is an ordinary member

It is reachable from the internet, so devices that cannot reach each other connect through it. It cannot read the traffic it passes on, because that traffic is encrypted between the two devices.

What you do with it

What members can do

Only members can connect to a device, and each device sets what every member may do to it: send it files and messages, use its forwarded services, or open a terminal on it.

Send files

Interrupted transfers resume, and each file is checked against its SHA-256 on arrival.

noscat send ./report.pdf npub1…

Chat

Chat in the terminal while noscat up runs, or send a single message from a script.

noscat chat npub1… lunch at noon?

Share a clipboard

Copy on one device and paste on another, across operating systems.

noscat clip npub1…

Forward ports

Reach a member's SSH server, web interface or database on a local port.

noscat forward npub1… --port 2222

Open a shell

Open the member's login shell in your terminal. The member asks first unless it already allows you.

noscat shell pi

Pipe data

Netcat mode connects stdin and stdout to another member.

echo hello | noscat pipe npub1…
Install

Install

The Linux packages are static builds with no dependencies, for x86_64 and ARM64 (including a Raspberry Pi running a 64-bit OS). Every package includes shell completions and a man page.

curl -fsSL https://raw.githubusercontent.com/Letdown2491/noscat/main/packaging/install.sh | sh

Installs into ~/.local/bin. Prefer a package? .deb, .rpm and .apk files are attached to every release.

brew install Letdown2491/tap/noscat

macOS (Intel and Apple Silicon) and Linux, with prebuilt bottles. brew services start noscat keeps it running.

[noscat]
SigLevel = Never
Server = https://nos.cat/x86_64

Add to /etc/pacman.conf (use aarch64 on ARM), then pacman -Sy noscat. Upgrades arrive with pacman -Syu.

scoop bucket add letdown2491 https://github.com/Letdown2491/scoop-bucket
scoop install noscat

Or grab the zip from the release page. winget support is in community review.

nix run github:Letdown2491/noscat

Linux and macOS, x86_64 and aarch64. Builds main; add ?ref=v0.7.0 for the release.

cargo install --locked noscat

Any platform with a Rust toolchain. On the BSDs it waits on an upstream fix: FreeBSD has a release binary, and INSTALL.md shows how to build there.

Open protocol

The protocol is documented

Everything Noscat sends is specified in a draft NIP, so other clients can be written against it. A White Noise account can also be invited into a mesh.
